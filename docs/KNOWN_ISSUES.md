## KI-4 · Two open planner tabs overwrite each other's library (incident 2026-10-11)
- **Symptom:** the planner keeps the whole library in browser localStorage and every tab holds its own in-memory copy; a save from one tab writes its copy over everything, silently dropping changes made in another tab since it loaded. On 2026-10-11 ~13:2x the conductor imported two teams from a tab loaded ten hours earlier and overwrote the owner's team rename ("Sal Z" → "Garchomp Z") and his new "Salamence" team in storage. The owner's own tab still held his state in memory.
- **Status:** WATCHING (an upstream design property of the app, not something this fork introduced). Unchanged 2026-10-11 ~17:50: the 13:3x incident was repaired through the app's UI (TODO / DONE history), and the `storage`-event fix is NOT built (queued as its own upstream-worthy PR — UPSTREAM-PLAN candidate H).
- **Why tolerated:** single-user, single-tab use never hits it; signed-in accounts sync through the server instead.
- **What would change it:** BUILT in planner PR #8 (2026-10-11): a `storage` event listener plus a per-record merge, and a pre-save staleness check (`revision`/`savedAt` on the stored envelope) so a tab merges before it writes instead of overwriting. Remains to verify: the owner's own two-tab use on the deployed build (then close KI-4); signed-in accounts still answer a 409 with "reload" (unchanged). Until verified: reload the tab before any write, and never write localStorage directly.
